# ➤ 系统日志文件关闭

麒麟系统中**系统日志文件**关闭处理，否则会持续变大占用系统存储

主用户目录下有 `xsession-errors` 和 `xsession-errors.old` 文件
- &emsp;● `xsession-errors` 文件是本机与服务之间通信错误的记录集合，体积会不断的增加。
- &emsp;● `xsession-errors.old` 是 `xsession-errors` 的备份文件，体积也会相应增加。
- 如果不定期清理的话，会不断增长，有的用户恐怖的增长到了几十个G。
- 对于个人用户来说，这个文件没必要留存，但删除之后系统又会自动创建，很是麻烦。

变通的解决办法就是删除掉这两个文件之后，再建相应的同名文件，再修改文件权限为不可写入，以后就不用但心这两个文件蚕食硬盘空间了。以下是相应的修改命令：

``` bash
cd ~/
rm .xsession-errors.old
touch .xsession-errors.old
sudo chattr +i .xsession-errors.old

rm .xsession-errors
touch .xsession-errors
sudo chattr +i .xsession-errors
```

# ➤ 系统审计软件长时间运行问题

![输入图片说明](./src/img/images/2026-09-02_11-38-43.png "")

在银河麒麟（Kylin）系统中，`auditd`（系统审计进程）占用内存过高是一个非常典型的已知问题。这通常是由于早期版本的 `auditd` 存在内存泄漏 Bug，导致进程在长期运行后，内部缓存和句柄无法自动释放，内存持续单向上涨，甚至可能挤占数据库或 Java 等核心业务进程的资源。

## 方案一:升级 audit 组件版本

如果服务器有安全合规需求，不能关闭审计服务，最彻底的解决办法是升级 `audit` 相关组件到修复了该 Bug 的版本（通常为 `3.0-5.se.08` 及以上版本）。

1、**检查当前版本**：
``` bash
rpm -qa | grep audit
```

![输入图片说明](./src/img/images/2026-09-02_11-48-45.png "")

(如果显示版本为 `3.0-5.se.06`，则存在泄漏风险)

2、**执行升级**（可通过官方源或手动上传 RPM 包）：
``` bash
# 使用 yum 升级
yum update audit audit-libs python3-audit

# 或者手动升级 RPM 包
rpm -Uvh audit-*.rpm audit-libs-*.rpm python3-audit-*.rpm
```

3、**重载并重启服务**：
``` bash
systemctl daemon-reload
systemctl restart auditd.service
```

## 方案二:关闭 auditd 服务（纯业务服务器适用）

如果服务器是纯业务服务器（如数据库、Java 服务），仅通过 SSH 进行运维，且没有等保合规的审计要求，可以直接关闭该服务以彻底杜绝内存泄漏。

1、**停止服务并释放内存**：
``` bash
systemctl stop auditd
```

2、**禁用开机自启**：
``` bash
systemctl disable auditd
```

3、**临时关闭内核审计开关（兜底防护）**：
``` bash
auditctl -e 0
```

## 方案三：重启服务（临时应急）

如果您正在排查生产环境的紧急卡顿问题，需要立即释放内存，可以直接重启 `auditd` 服务。重启后，其占用的内存会瞬间释放。

``` bash
systemctl restart auditd
```

> ⚠️ ***注：*** *这只是治标不治本的应急手段，内存会在后续运行中再次缓慢累积。*

## 方案四：定时重启服务（推荐）

创建一个定时任务，**每天凌晨**执行重启一次 `auditd` 服务。

``` bash
# 防止 auditd 内存泄漏持续累积
0 0 * * * /usr/bin/systemctl restart auditd
```

> ⚠️ **注**：建议使用命令的绝对路径（`/usr/bin/systemctl`），避免 cron 环境变量中 PATH 不完整导致执行失败。可以通过 `which systemctl` 确认路径。
